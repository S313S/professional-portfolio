# GPT-5.6 视觉调试证据闭环设计

## 背景

作品集已经具备多组仅开发模式可访问的独立调试页面，包括友人帐热点校准、Career、Works 和 Codex Report。它们解决的核心问题并不是单纯生成代码，而是把“这个视觉位置感觉不对”一类难以精确表达的判断，转化为可控制、可确认、可回写的参数。

本次扩展不改变公开个人品牌网站，而是把现有 `Codex Report Panel` 扩展为一条可检查的视觉调试证据链，真实记录人工视觉判断如何经过调试界面、GPT-5.6/Codex 实施和自动测试，最终成为源代码改进。

## 目标

- 在 `/debug/codex-report` 中集中呈现视觉调试任务的完整生命周期。
- 关联已有独立调试路由，不重造视觉调参工具。
- 记录问题、人工校准、源码改动、测试结果和时间戳。
- 支持导出适合提交到仓库的 Markdown 证据文档。
- 兼容现有 `codex-report.json` 数据，不影响已有操作指南。
- 保证所有新增入口只在开发模式出现，生产站点体验保持不变。

## 非目标

- 不把调试面板公开部署到个人品牌网站。
- 不把所有现有调试页面抽象为通用低代码编辑器。
- 不修改 Career、Works、友人帐等沉浸式页面的视觉参数。
- 不把工具自身记录包装成模型身份的系统级认证。
- 不追溯声称旧调试工具由 GPT-5.6 创建。

## 方案选择

采用“扩展 Codex Report 为视觉调试证据闭环”的方案。

相比抽象通用调参框架，该方案改动范围更收敛，能直接复用已有调试页面和测试；相比静态证据看板，它能够表达真实的工作流状态和机器可读数据，更适合演示 GPT-5.6 如何参与实施与验证。

## 页面结构

保留 Codex Report 现有左侧导航和操作指南，在导航中新增 `Visual Debug Evidence` 分组。证据详情区域按以下顺序展示：

1. 难以用语言描述的视觉问题。
2. 对应的独立调试页面链接。
3. 人工确认的参数和备注。
4. GPT-5.6/Codex 完成的修改摘要与源码文件。
5. 已执行的测试命令和结果。
6. 问题创建、参数确认、实施和验证时间。

Career、Works 和友人帐调试路由可以作为证据记录的目标入口，但本次只扩展证据组织能力，不改造这些页面内部的调参机制。

## 数据模型

证据记录采用四阶段状态：

```text
问题描述 -> 人工校准 -> GPT-5.6/Codex 实施 -> 测试验证
```

每条记录包含：

- 稳定的记录 ID 和标题。
- 问题描述、视觉意图和调试路由。
- 人工确认摘要与键值参数。
- 实施摘要、改动文件和模型说明。
- 测试命令、测试结果与验证结论。
- 各阶段时间戳。

模型说明只能记录为“当前任务由用户确认使用 GPT-5.6”等准确表述。它是辅助证据，不替代 Codex Session、截图或平台日志对模型使用情况的证明。

## 数据流

1. 用户或 Codex 创建一条视觉问题记录。
2. 用户通过记录中的链接进入现有独立调试页。
3. 用户调整并确认参数，调试页继续写入其现有本地输出。
4. GPT-5.6/Codex 根据确认结果修改源码并运行测试。
5. Codex 将真实改动文件、测试命令和结果补入证据记录。
6. Codex Report 展示完整状态，并将记录导出为 Markdown。
7. 已完成的真实记录作为 Build Week 证据文档提交到仓库。

运行态证据保存在 `tmp` 下的本地 JSON 中。默认数据和解析逻辑保持向后兼容；旧版报告中没有证据字段时，页面仍正常显示原有指南。

## 异常处理

- 缺少证据文件时展示空状态或默认记录，不阻断原有报告。
- 缺少可选阶段字段时，根据已存在数据计算当前阶段。
- JSON 数据无效时回退到安全默认值，并在调试页面显示可理解的错误提示。
- 调试路由为空或不属于允许列表时不生成可点击的站外链接。
- 导出逻辑只序列化已记录的事实，不补造缺失测试或时间戳。

## 测试策略

- 纯逻辑测试：数据规范化、旧数据兼容、阶段计算和 Markdown 导出。
- React 渲染测试：新导航分组、证据阶段、调试路由和空状态。
- 回归验证：现有 Codex Report、Standalone Route 和友人帐调试测试。
- 工程验证：TypeScript 检查和生产构建。
- 浏览器验证：本地进入 `/debug/codex-report`，走通一条问题、校准、实施和验证记录的展示流程。

## 验收标准

- `/debug/codex-report` 能展示至少一条真实完成的视觉调试证据记录。
- 每条完整记录均能追溯到调试路由、源文件和测试命令。
- Markdown 导出内容与页面记录一致，可加入仓库提交。
- 旧报告数据和现有调试路由测试继续通过。
- 生产构建中没有公开调试入口，个人品牌网站行为不变。
