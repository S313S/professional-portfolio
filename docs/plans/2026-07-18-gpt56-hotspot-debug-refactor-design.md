# GPT-5.6 热点调试页小幅重构设计

## 背景

`/debug/friend-book-diff-hotspots` 是比赛前已经存在的开发调试页。它能够选择友人帐找不同场景与目标，在左右预览中拖动、缩放红色热点框，并把当前参数保存到 `tmp/friend-book-diff-hotspots.json`。

本次 OpenAI Build Week 工作不把旧工具追溯归因为 GPT-5.6 从零创建，而是记录一次由用户确认使用 GPT-5.6 的真实重构：GPT-5.6 扫描现有页面，识别其工作流说明不足，并在不改变核心校准能力的前提下改善页面的信息层级和证据入口。

## 扫描发现

在约 649px 宽的应用内浏览器视口中：

- 左右两张预览纵向排列。
- 参数面板从页面约 `y=960px` 才出现，首屏看不到选择和确认动作。
- 页首只说明拖动和缩放，没有解释完整的“选择—校准—确认”过程。
- 页面没有直接说明为什么这种工具对人机协作有价值，也没有链接到 `/debug/codex-report` 的证据记录。

## 设计目标

1. 在首屏明确说明本次页面是 GPT-5.6 对既有工具的重构与扩展。
2. 用 `Select → Calibrate → Confirm` 三步流程解释操作闭环。
3. 在窄屏告诉用户参数与确认面板位于预览下方，减少“只有预览、没有控制”的困惑。
4. 增加到 Codex Report 证据页的开发环境入口。
5. 保留所有现有拖拽、缩放、重置、代码导出和保存行为。

## 方案选择

### 方案 A：仅替换标题

风险最小，但无法解决流程不清晰，也不能形成有说服力的重构证据。

### 方案 B：小幅工作流重构（采用）

增加诚实归因、三步流程卡、窄屏提示、参数面板语义说明和证据入口。保留现有页面结构与交互逻辑，改动集中在 `FriendBookDiffHotspotsDebugPage.tsx`。

### 方案 C：重做响应式双栏与交互

可以让参数面板在小屏更靠前，但会改变原有操作顺序和视觉布局，验证成本明显更高，不符合“稍微改改”的范围。

## 页面结构

页首由四层信息组成：

1. `GPT-5.6 REFACTOR · OPENAI BUILD WEEK 2026` 眉题。
2. 保留可识别的工具名称 `Friend Book Diff Hotspots Debug`。
3. 一句诚实说明：既有视觉调试工具由当前 GPT-5.6 Codex 任务重构与扩展。
4. 三个紧凑步骤：选择场景和目标、在左右预览中校准、确认并保存机器可读参数。

参数面板增加一句“Human judgment → machine-readable parameters”的解释，并把确认按钮文案改为更明确的 `Confirm calibrated hotspots`。页首提供 `/debug/codex-report` 链接，供评委或开发者查看证据链。

## 响应式策略

- 桌面端维持预览区加右侧参数面板的双栏结构。
- 窄屏继续纵向排列，避免重新设计拖拽区域。
- 页首新增仅在窄屏显示的提示，说明参数面板位于两张预览之后。
- 不使用固定悬浮控制，避免遮挡热点预览。

## 证据与归因边界

允许的表述：

> GPT-5.6 refactored and extended the existing visual hotspot debugging tool.

不允许的表述：

> GPT-5.6 built the original hotspot debugging tool from scratch.

仓库证据包括本次设计文档、实施计划、失败后通过的渲染测试、源码提交、README 说明、Codex Report 记录和最终浏览器验证。

## 验证标准

- 渲染测试能定位 GPT-5.6 重构归因、三步流程和证据链接。
- 原有场景选择、目标选择、左右预览、导出文本框和确认按钮仍存在。
- 逻辑测试、TypeScript 检查与生产构建通过。
- 浏览器中桌面/窄屏页面无控制台错误，三步流程和窄屏提示可见。
- 公开首页不新增调试入口。
